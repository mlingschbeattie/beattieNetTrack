The OS is the manager of a computer -- it hands out jobs to hardware, manages files, lets you run programs, and keeps everything organized. For A+, you need to know Windows thoroughly, with working knowledge of Linux and macOS for comparison.

## Windows OS Overview

| Feature | Details |
|---|---|
| **Windows 10 / 11** | Current desktop versions -- Home, Pro, and Enterprise editions |
| **Windows Server** | Domain controller, file sharing, centralized management |
| **User Accounts** | Standard (limited) vs Administrator (full system access) |
| **NTFS Permissions** | Full Control, Modify, Read & Execute, Read, Write |
| **FAT32** | Older file system -- no permissions, 4 GB max file size |
| **Registry** | Centralized database of Windows settings (regedit.exe) |
| **Task Scheduler** | Automates tasks on a schedule |

NTFS is the default Windows file system. **FAT32 does NOT support file-level permissions** -- this is a common exam question.

## Linux OS Overview

| Feature | Details |
|---|---|
| **Distributions** | Ubuntu, Debian, CentOS, Red Hat, Fedora (distro = Linux + package ecosystem) |
| **Root User** | Superuser with unlimited system access |
| **sudo** | Run a single command with elevated privileges (safer than logging in as root) |
| **File Permissions** | rwx (read/write/execute) for owner, group, and others |
| **Package Managers** | apt (Debian/Ubuntu), yum/dnf (Red Hat/CentOS), snap |
| **Cron Jobs** | Schedule recurring tasks (crontab -e to edit) |

Linux is **case-sensitive** -- `File.txt` and `file.txt` are different files.

## macOS Overview

| Feature | Details |
|---|---|
| **Versions** | Sequoia, Sonoma, Ventura, Monterey (annual release cycle) |
| **Admin Account** | Full system access |
| **Standard Account** | Limited user account |
| **File Permissions** | Unix-style rwx (same model as Linux) |
| **Finder** | Graphical file manager (equivalent to Windows Explorer) |
| **Terminal** | Unix command line -- bash or zsh shells |
| **System Settings** | Equivalent to Windows Control Panel |
| **Disk Utility** | Equivalent to Windows Disk Management |

## Install & Recovery Options

| Method | Description |
|---|---|
| **In-Place Upgrade** | Installs new OS over existing -- keeps files and settings |
| **Clean Install** | Wipes the drive, fresh OS from scratch |
| **Recovery Environment (WinRE)** | Repair boot issues, restore images, access command prompt |
| **Boot Media** | USB installer for Windows or Linux -- set in UEFI boot order |

Always back up data before any OS upgrade or recovery operation.

## Windows Admin Tools

| Tool | Purpose |
|---|---|
| **Task Manager** | View running processes, performance graphs, startup apps |
| **Device Manager** | Manage drivers and hardware; yellow exclamation = driver issue |
| **Disk Management** | Create/delete/format partitions and volumes |
| **Services.msc** | Start/stop/configure background services |
| **Msconfig** | Boot options, safe mode, startup program control |
| **Event Viewer** | System, Application, and Security logs for troubleshooting |
| **regedit** | Windows Registry editor (use carefully!) |

## Linux Command Essentials

| Command | Purpose |
|---|---|
| `ls / cd / pwd` | List directory, change directory, print working directory |
| `cp / mv / rm` | Copy, move, delete files |
| `chmod` | Change file permissions (e.g., `chmod 755 script.sh`) |
| `chown` | Change file ownership |
| `ps / top` | List processes / live resource usage monitor |
| `ip a / ping` | Show network interfaces / test connectivity |
| `apt install` | Install a package (Debian/Ubuntu) |
| `sudo` | Run a command as root |

### chmod Permission Notation

```
chmod 755 file.sh
  7 = rwx (owner: read + write + execute)
  5 = r-x (group: read + execute)
  5 = r-x (others: read + execute)

chmod 644 file.txt
  6 = rw- (owner: read + write)
  4 = r-- (group: read only)
  4 = r-- (others: read only)
```

## Virtualization & Cloud Basics

| Concept | Details |
|---|---|
| **Hypervisor** | Software that runs virtual machines |
| **Type 1 (Bare-Metal)** | Runs directly on hardware (VMware ESXi, Hyper-V) |
| **Type 2 (Hosted)** | Runs inside a host OS (VirtualBox, VMware Workstation) |
| **VM Resources** | Each VM gets allocated vCPU, vRAM, and virtual disk |
| **Snapshots** | Point-in-time VM state save -- quick rollback |
| **Containers** | Lightweight app isolation sharing the host OS kernel (Docker) |
| **IaaS / PaaS / SaaS** | Infrastructure / Platform / Software as a Service (cloud models) |

## Exam Focus

**Windows:**
- NTFS supports permissions; FAT32 does not
- Task Manager: Processes, Performance, Startup tabs
- Event Viewer: System, Application, Security logs
- Device Manager: yellow ! = driver problem

**Linux:**
- `chmod 755` = rwx r-x r-x
- `sudo` grants single-command elevation; safer than logging in as root
- `/home` = user home directories
- `/root` = root user's home directory
- Linux file system is case-sensitive

**macOS:**
- System Settings = Windows Control Panel equivalent
- Disk Utility = Windows Disk Management equivalent
- Terminal for admin tasks (bash/zsh)

## Key Facts

- Always back up before an OS upgrade
- Boot order is set in UEFI/BIOS
- Safe Mode (Windows): troubleshooting mode with minimal drivers
- System Restore: reverts Windows to a previous restore point
- User profiles contain personal settings and data
- Permissions use **inheritance** -- child folders inherit parent permissions by default
- **Ownership** is required to change permissions on an object

## Practical Exercises

1. **Create Users** -- Create a standard user and an admin user; compare what each can access
2. **Permission Test** -- Create a folder, set it to read-only for standard users, and verify the restriction
3. **Find Logs** -- Open Windows Event Viewer; locate a recent Warning in the System log
4. **CLI Basics** -- In a terminal (Windows CMD or Linux bash), practice: `ls`/`dir`, `cd`, `mkdir`, `rm`/`del`
5. **chmod Practice** -- On Linux (or WSL), create a file and use `chmod` to set 755 then 644 permissions; verify with `ls -l`
