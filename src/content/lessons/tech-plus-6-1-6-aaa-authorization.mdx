## What Are You Allowed to Touch?

You present your driver's license at airport security. The TSA officer scans your barcode and verifies that you are genuinely John Doe (**Authentication**).

*Does that mean you can open the door to the cockpit and fly the Boeing 777?* **Of course not.**

Once an identity is verified, the system must consult an access policy to determine what actions, directories, files, and commands that specific identity is permitted to execute.

This is **Authorization**: the second "A" in the **AAA Framework**.

Understanding access control models like **RBAC**, **DAC**, and **MAC**, and enforcing the **Principle of Least Privilege** is what prevents rogue insiders and compromised accounts from destroying corporate infrastructure.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        AUTHENTICATION VS. AUTHORIZATION                │
├──────────────────────────────────┬─────────────────────────────────────┤
│ **Authentication (The Badge)**   │ **Authorization (The Keys)**        │
├──────────────────────────────────┼─────────────────────────────────────┤
│ 🔑 Question: **"Who are you?"**  │ 🚪 Question: **"What can you do?"** │
│ • Validates identity credentials │ • Checks permissions and rights     │

│                                  │   but CANNOT delete databases."*    │
└──────────────────────────────────┴─────────────────────────────────────┘
```

## 1. Access Control Models: How Permissions Are Assigned

Computer operating systems and enterprise applications use different architectural models to manage who gets access to what:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ACCESS CONTROL MODEL TAXONOMY                   │
├──────────────┬─────────────────────────────────────────────────────────┤
│ **RBAC**     │ **Role-Based Access Control:** Permissions belong to    │
│ (Enterprise) │ **Roles** (e.g. "Nurse", "Manager"). Users are placed in│
│              │ roles. Simplest to manage in large organizations.       │
├──────────────┼─────────────────────────────────────────────────────────┤
│ **DAC**      │ **Discretionary Access Control:** The **Owner** of the  │
│ (Desktop OS) │ file decides who has access (Windows NTFS, Linux chmod).│
├──────────────┼─────────────────────────────────────────────────────────┤
│ **MAC**      │ **Mandatory Access Control:** The **System/OS** enforces│
│ (Military)   │ access using security labels (Top Secret / Secret).     │
│              │ Users cannot modify or override labels.                 │
├──────────────┼─────────────────────────────────────────────────────────┤
│ **ABAC**     │ **Attribute-Based Access Control:** Contextual policies │
│ (Next-Gen)   │ evaluating attributes (User Role + Device + Time + IP). │
└──────────────┴─────────────────────────────────────────────────────────┘
```

### Role-Based Access Control (RBAC): The Corporate Standard
In a company with 5,000 employees, you cannot manually assign 200 file permissions to individual user names.
- You create an Active Directory group called `Finance_Dept`.
- You assign read/write permissions for the accounting software to `Finance_Dept`.
- When an employee is hired into accounting, you simply add them to that group—they instantly inherit all necessary permissions!

## 2. The Principle of Least Privilege in Action

The **Principle of Least Privilege (PoLP)** dictates that users, processes, and service accounts should receive **only the absolute minimum permissions required** to perform their assigned job duties.

```
┌────────────────────────────────────────────────────────────────────────┐
│                    THE BLAST RADIUS OF COMPROMISED ACCOUNTS            │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   ❌ BAD PRACTICE (Over-Privileged User):                              │
│   Accountant logs in with full Domain Admin rights.                    │
│   └── Clicks malicious phishing link $\rightarrow$ Malware infects     │
│       entire corporate network, deletes domain backups!                │
│                                                                        │
│   ✔ BEST PRACTICE (Least Privilege):                                   │
│   Accountant logs in with Standard Restricted User permissions.        │
│   └── Clicks malicious phishing link $\rightarrow$ Malware is blocked  │
│       from installing system drivers and cannot spread!                │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

<Callout type="exam">
**The Dual Account Standard:** System administrators should never check daily email or browse the web while logged in as `Domain Admin` or `root`. Administrators should have two accounts: a standard `user` account for daily tasks, and a separate `admin_user` account used only when executing elevated configuration changes.
</Callout>

## 3. Separation of Duties

In cybersecurity and financial compliance, **Separation of Duties** prevents fraud and accidental sabotage by requiring **two or more distinct people** to complete a critical business transaction:
- Person A creates a new vendor profile in the database.
- Person B approves the purchase order.
- Person C releases the wire transfer payment.

If one person had permissions to perform all three actions, they could easily steal millions of dollars with no oversight.

---

## Why This Matters in the Field

When you manage user onboarding tickets or configure folder permissions on a network share, setting proper authorization protects your organization.

Implementing RBAC and enforcing least privilege ensures that an employee opening a malicious email attachment does not bring down the entire company.
