## Trusting What the Screen Says

Imagine logging into your bank account. You see your balance is $5,000. 

Now imagine that an attacker has infiltrated the bank's database server. They don't steal the money—they just change a few lines of code so that every time you transfer $50 to pay your electric bill, the bank transfers $500 instead.

The data is 100% confidential (nobody leaked your balance) and 100% available (the website is online). But the system is completely broken because you **cannot trust the accuracy of the data**.

**Integrity** is the "I" in the **CIA Triad**. It is the absolute guarantee that data has not been altered, deleted, injected, or corrupted—whether by a malicious hacker, a rogue employee, a software bug, or a physical hard drive error.

## 2. Cryptographic Hashing: The Ultimate Tamper Evident Seal

A **Cryptographic Hash Function** is a one-way mathematical algorithm that takes any file (a 1-sentence text file or a 50 GB video game) and computes a fixed-length string of hex characters called a **Hash Value (or Message Digest)**:

1. **One-Way (Irreversible):** You can easily calculate a hash from a file, but it is mathematically impossible to reconstruct the original file from the hash.
2. **Deterministic:** The exact same file will ALWAYS produce the exact same hash value on every computer on Earth.
3. **The Avalanche Effect:** If you change a single letter or a single binary bit in a 10 GB file, the resulting hash value changes completely and unpredictably!

```
┌────────────────────────────────────────────────────────────────────────┐
│                      HASH ALGORITHM COMPARISON                         │
├──────────────┬───────────────┬─────────────────────────────────────────┤
│ Algorithm    │ Digest Length │ Cryptographic Security Status           │
├──────────────┼───────────────┼─────────────────────────────────────────┤
│ **MD5**      │ 128 Bits      │ ❌ **BROKEN** (Collision vulnerabilities)│
│ **SHA-1**    │ 160 Bits      │ ❌ **DEPRECATED** (Do not use for certs) │
│ **SHA-256**  │ 256 Bits      │ 🏆 **CURRENT INDUSTRY GOLD STANDARD**   │
│ **SHA-3**    │ 256–512 Bits  │ 🏆 Modern sponge-construction standard  │
└──────────────┴───────────────┴─────────────────────────────────────────┘
```

<Callout type="exam">
**The Hash Comparison Rule:** When you download an ISO installer for an operating system (e.g. `ubuntu-24.04.iso`), the website publishes its known SHA-256 hash. After downloading, you run `Get-FileHash ubuntu-24.04.iso` in PowerShell. If the hashes match 100%, you know with mathematical certainty that the file was not corrupted during download and was not modified by an attacker!
</Callout>

## 3. Digital Signatures: Integrity + Non-Repudiation

A hash proves that a file was not altered, but it doesn't prove *who created it*.

A **Digital Signature** combines cryptographic hashing with **Asymmetric Public-Key Cryptography**:
1. The author calculates a hash of the software update.
2. The author encrypts that hash using their **Private Key**.
3. Your computer downloads the software, decrypts the signature using the author's public key, and recalculates the hash.
4. If the hashes match, your computer verifies two things simultaneously:
   - **Integrity:** The software was not modified in transit.
   - **Authentication:** The software came genuinely from the verified vendor.

---

## Why This Matters in the Field

When troubleshooting corrupt database files, validating downloaded system firmware updates, or defending server audit logs against malicious tampering, verifying cryptographic hashes and digital signatures is the technician's primary tool for guaranteeing data trust.
