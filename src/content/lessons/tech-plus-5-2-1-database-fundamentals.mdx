## Database Fundamentals

A **database** is an organized collection of structured data. A **Database Management System (DBMS)** is the software that creates, maintains, and provides access to a database. Together, they replace manual file management with a reliable, searchable, multi-user system.

### Why Databases?

Without a database, storing thousands of student records in text files would be:
- Slow to search
- Error-prone when updating
- Inaccessible to multiple users at once
- Difficult to secure

A database solves all of these problems.

### Relational Database Concepts

**Relational databases** store data in **tables** (also called relations). Every table consists of:

- **Column (field)** — defines a data attribute: name, date, score
- **Row (record)** — a single entry in the table

**Example: Students table**

| student_id | first_name | last_name | grade_level | gpa |
|---|---|---|---|---|
| 1 | Alice | Johnson | 11 | 3.85 |
| 2 | Bob | Martinez | 10 | 3.42 |
| 3 | Carol | Lee | 12 | 3.91 |

**Primary Key** — a column (or combination) that uniquely identifies each row. In the example above, `student_id` is the primary key. No two rows can have the same primary key value.

**Foreign Key** — a column in one table that references the primary key in another table, linking the two tables.

### DBMS Examples

| DBMS | Type | Notes |
|---|---|---|
| **MySQL** | Relational (open source) | Most popular web database; used by WordPress, many web apps |
| **PostgreSQL** | Relational (open source) | Advanced features; preferred for complex applications |
| **Microsoft SQL Server** | Relational (commercial) | Common in enterprise Windows environments |
| **SQLite** | Relational (embedded) | Single-file database; used in mobile apps, browsers |
| **Oracle Database** | Relational (commercial) | Enterprise; banking, government, ERP systems |
| **MongoDB** | Non-relational (document) | JSON documents; popular for web/mobile backends |

### SQL — Structured Query Language

**SQL** is the standard language for interacting with relational databases. Four fundamental operations (CRUD):

**CREATE — Insert new data:**
```sql
INSERT INTO students (first_name, last_name, grade_level, gpa)
VALUES ('Diana', 'Smith', 11, 3.70);
```

**READ — Query/retrieve data:**
```sql
SELECT first_name, last_name, gpa
FROM students
WHERE grade_level = 11
ORDER BY gpa DESC;
```

**UPDATE — Modify existing data:**
```sql
UPDATE students
SET gpa = 3.95
WHERE student_id = 1;
```

**DELETE — Remove data:**
```sql
DELETE FROM students
WHERE student_id = 3;
```

### CRUD Operations Summary

| Operation | SQL Command | Description |
|---|---|---|
| **Create** | `INSERT INTO` | Add new records |
| **Read** | `SELECT ... FROM` | Query/retrieve records |
| **Update** | `UPDATE ... SET` | Modify existing records |
| **Delete** | `DELETE FROM` | Remove records |

### Relational vs. Non-Relational (NoSQL)

| Feature | Relational | Non-Relational (NoSQL) |
|---|---|---|
| Structure | Tables with fixed columns | Documents, key-value, graph, column |
| Schema | Fixed, predefined | Flexible / schema-less |
| Query language | SQL | Varies (MongoDB Query Language, etc.) |
| Best for | Structured, consistent data | Unstructured, rapidly changing, large-scale |
| Examples | MySQL, PostgreSQL, SQL Server | MongoDB, Redis, Cassandra, DynamoDB |

### SQL Injection — Security Alert

**SQL injection** (OWASP #3 — Injection) is the most common database attack. Malicious SQL code is inserted through an input field and executed by the database.

Example of vulnerable code query:
```
"SELECT * FROM users WHERE username='" + userInput + "';"
```

If `userInput = "' OR '1'='1"`, the query becomes:
```sql
SELECT * FROM users WHERE username='' OR '1'='1';
```

This returns all users — authentication bypassed.

**Defense:** Always use **parameterized queries** (prepared statements) — never build SQL strings by concatenating user input.

### Key Exam Points

- A **database** stores organized data; a **DBMS** manages access to it
- **Table** = rows (records) + columns (fields)
- **Primary key** = uniquely identifies each row; **foreign key** = links to another table's primary key
- CRUD: **Create** (INSERT), **Read** (SELECT), **Update** (UPDATE), **Delete** (DELETE)
- **SQL injection** is OWASP #3 — use parameterized queries, never concatenate user input into SQL
- **NoSQL** databases store data in documents/key-value pairs instead of tables — flexible schema
