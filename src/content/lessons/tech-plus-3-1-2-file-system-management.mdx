## Path Hierarchies: Windows Drive Letters vs. Linux Unified Root

Operating systems organize files into tree hierarchies, but they structure the base of the tree differently:

### 1. Windows Drive Letter Hierarchy
Windows assigns a capital letter followed by a colon and backslash to every physical storage volume or mounted partition:
- **`C:\` (Primary System Volume):**
  - `C:\Windows\` — Core operating system binaries and drivers.
  - `C:\Program Files\` — 64-bit application software.
  - `C:\Program Files (x86)\` — Legacy 32-bit application software.
  - `C:\Users\[Username]\` — User profile directory (Desktop, Downloads, Documents).
- **`D:\`, `E:\`, `F:\`:** Secondary internal SSDs, optical disc drives, or mapped network drives.
- **Path Separator:** Windows uses the **Backslash (`\`)**.

### 2. Linux and macOS POSIX Unified Hierarchy
Unix-like systems have **no drive letters**. Everything—internal NVMe drives, USB sticks, network shares, and even hardware devices—is mounted under a single root directory:
- **`/` (The Root Directory):** The absolute top of the entire filesystem tree.
- `/home/[username]/` (Linux) or `/Users/[username]/` (macOS) — User profile data.
- `/bin/` and `/usr/bin/` — Core executable programs and command utilities.
- `/etc/` — System-wide configuration files (networking, services, security).
- `/var/log/` — System, security, and application error logs.
- **Path Separator:** Linux/macOS uses the **Forward Slash (`/`)**.

### Absolute vs. Relative Paths
- **Absolute Path:** The complete, unambiguous address starting from the root of the filesystem (e.g. `C:\Users\Admin\Logs\app.log` or `/var/log/nginx/access.log`). It points to the exact same file regardless of where your terminal is currently located.
- **Relative Path:** A path calculated from your **Current Working Directory (CWD)**.
  - `.` represents the current folder.
  - `..` represents the parent folder one level up. (e.g., `cd ..` moves up one folder).

## Core Command-Line File Operations

GUI File Explorers are intuitive, but command-line file management is scriptable, faster, and works across headless remote servers:

| Action | Windows GUI | Windows Command Prompt | Linux / macOS Shell (Bash/Zsh) |
|---|---|---|---|
| **List Files** | View in Explorer | `dir` | `ls -la` |
| **Change Directory** | Double-click folder | `cd [foldername]` | `cd [foldername]` |
| **Move Up Directory** | Click Up Arrow | `cd ..` | `cd ..` |
| **Create Directory** | Right-click → New Folder | `mkdir [name]` | `mkdir [name]` |
| **Copy File** | Ctrl + C / Ctrl + V | `copy [source] [dest]` | `cp [source] [dest]` |
| **Move / Rename File** | Drag / Press F2 | `move [source] [dest]` | `mv [source] [dest]` |
| **Delete File** | Press Delete key | `del [filename]` | `rm [filename]` |
| **Delete Folder** | Press Delete key | `rmdir /s [folder]` | `rm -rf [folder]` |

## File Extensions, Associations, and Security Hazards

A filename consists of two parts: the base name and the **file extension**:

**payroll\_q3.xlsx**

- **The Extension (`.xlsx`):** A suffix (usually 3 to 4 characters) following a period that identifies the file format and tells the OS which default program to launch when double-clicked.
- **File Associations:** Windows maps extensions in the registry (e.g., `.docx` launches Microsoft Word, `.pdf` launches Adobe Acrobat, `.py` opens Python).

```
┌────────────────────────────────────────────────────────┐
│              THE DOUBLE-EXTENSION MALWARE TRAP         │
│                                                        │
│   Windows hides extensions by default:                 │
│   What user sees:    [📄 invoice_august.pdf       ]    │
│   What it really is: [⚠️ invoice_august.pdf.exe   ]    │
│                                                        │
│   Result: User thinks it is an invoice, clicks it,     │
│           and executes a ransomware binary!            │
└────────────────────────────────────────────────────────┘
```

<Callout type="exam">
**Security Hardening Rule:** In Windows File Explorer, always navigate to **View → Show → File name extensions**. Hiding extensions is a major security vulnerability because attackers name trojan malware `resume.pdf.exe` or `receipt.docx.vbs`. If extensions are hidden, the victim only sees `resume.pdf` with an Acrobat icon!
</Callout>

## File Permissions and Access Control Lists (ACLs)

In multi-user corporate environments, files must be protected against unauthorized modification or viewing.

### Windows NTFS Permissions
Configured under **File Properties → Security**:
- **Full Control:** Can read, modify, delete, and change file ownership/permissions. (Reserved for Administrators).
- **Modify:** Can read, edit, overwrite, and delete files, but cannot change security permissions.
- **Read & Execute:** Can view file contents and run executable scripts/programs.
- **Read:** Can view contents and attributes only.
- **Write:** Can create new files and append data, but cannot view existing files.

### Permission Inheritance
By default, any new subfolder or file created inside a directory automatically **inherits** the security permissions of its parent folder. To create a private folder within a shared company drive, an administrator must **disable inheritance** and explicitly configure custom access lists.
