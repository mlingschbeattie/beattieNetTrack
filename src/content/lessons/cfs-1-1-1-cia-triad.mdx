## The 8:00 AM Call That Teaches You the Triad

You're ten minutes into your shift in the school NOC when the radio crackles: "The grading server is down." You pull up the console. The server is responding to pings, the CPU is idling at two percent, and the network link light is solid green. Windows says the service is running. But when the assistant principal logs in, every student record has been renamed to `.locked` and an unreadable text file sits on the desktop demanding two Bitcoin.

The server isn't down. The hardware is fine. The operating system is fine. But your data is completely inaccessible. That's an Availability failure wrapped in an encryption lock.

Next day, opposite problem: the attendance server is online, files are open, nobody demanded a ransom. But a student worker noticed that three seniors with seventy unexcused absences suddenly show perfect attendance in the database. Nothing crashed. Nobody got locked out. But the data cannot be trusted. That's an Integrity failure.

Both times, someone ran down the hall shouting "we've been hacked." The reason you don't panic is that you have a mental checklist. You isolate which property failed before you touch a keyboard. In security operations, that framework is the CIA Triad — Confidentiality, Integrity, and Availability. Every firewall rule, encryption algorithm, access control list, and backup schedule exists to defend one of these three walls.

## Confidentiality: Keeping Secrets Secret

Confidentiality means only authorized entities can read the data. If someone views, copies, or downloads information they aren't supposed to see — even if they change nothing and leave the server online — confidentiality has failed.

Think of confidentiality like an armored courier pouch. You seal payroll records inside. If an attacker intercepts the van, slices the pouch open, takes photos of every employee's salary on their phone, and puts the papers right back into the pouch, the company still has the papers. Operations continue. But the secret is out in the wild.

In enterprise networks, confidentiality fails through misconfigured permissions and sloppy transport. An administrator leaves an AWS S3 cloud storage bucket set to "Public Read," exposing fifty thousand applicant resumes to any web scraper that scans the IP range. A technician tests an internal API over raw HTTP instead of HTTPS, sending cleartext passwords across the local coffee shop Wi-Fi where anyone running Wireshark can harvest them in real time. Full-disk encryption (FDE) with BitLocker or LUKS protects data at rest when a laptop is stolen from a car; TLS 1.3 protects data in transit across the wire.

<Callout type="exam">
CompTIA loves testing the difference between encryption at rest and encryption in transit. If a stolen laptop has BitLocker enabled, the data is protected at rest. If an attacker intercepts web traffic on an open wireless network, TLS protects the data in transit. Know the controls for both.
</Callout>

## Integrity: Trusting What You Read

Integrity guarantees that information and systems remain accurate, complete, and untampered by unauthorized actors. A system with broken integrity is often more dangerous than a system that crashed completely — because you keep making decisions based on poisoned data.

Consider an infusion pump in a hospital room. If an attacker cuts power to the pump, alarms ring immediately and nurses switch to manual IV bags — an Availability failure that announces itself loudly. But if an attacker quietly alters the firmware configuration on the pump so that every five-milligram dosage of medication is delivered as fifty milligrams, no alarm sounds. The machine reports that everything is operating normally while delivering lethal overdoses. That is the horror of an unmonitored Integrity failure.

Defenders verify integrity mathematically using cryptographic hash functions like SHA-256. A hash function takes any input — a single word, a photo, or a five-gigabyte Linux installer ISO — and runs it through a one-way mathematical meat grinder to produce a fixed-length string of characters. If even one bit of that five-gigabyte file changes from a zero to a one, the resulting hash changes completely. When software vendors publish an installer, they publish the SHA-256 hash next to it. You run `sha256sum` on your downloaded copy. If the strings match down to the last character, the file is authentic. If one letter is off, the file was corrupted or injected with malware.

<Callout type="warn">
Students consistently confuse confidentiality and integrity. Encryption gives you confidentiality — it keeps people from reading the message. Hashes give you integrity — they prove nobody tampered with the message. Encrypting a file does not stop an attacker from deleting random bytes out of the middle of it. You need both.
</Callout>

## Availability: Ensuring Systems Are Reachable When Needed

Availability means authorized users can reach the systems, networks, and data they need to do their jobs without arbitrary disruption. If your email server is mathematically impenetrable and your databases have never been altered, but your edge router is dropping ninety-nine percent of incoming packets because an external botnet is blasting it with UDP amplification traffic, your security score is zero.

Availability is defended with architecture, not passwords. You build N+1 redundancy into server power supplies so a blown capacitor doesn't crash a hypervisor. You deploy cloud load balancers that distribute incoming web requests across four redundant virtual machines instead of one fragile desktop under a desk. And you enforce the immutable 3-2-1 backup rule: three total copies of your data, stored on two different media types, with at least one copy kept completely offline or air-gapped where network ransomware cannot touch it.

<Callout type="tip">
When you write backup scripts, remember that automated network shares are vulnerable to ransomware. If your backup server is mapped as a drive letter on your domain controller, the ransomware will encrypt your backups thirty seconds after it encrypts the server. True availability requires immutable, offline, or write-once storage.
</Callout>

## The Modern Attack: Double Extortion

Ransomware used to be purely an Availability attack. A technician clicked a malicious macro in an email attachment, the malware encrypted local files, and an on-screen note demanded fifty dollars in prepaid cards to restore access. If you had good nightly tape backups, you wiped the machine, restored the drive, and lost half a day of work.

Modern ransomware operators don't work that way. When they breach a corporate network, they spend three weeks quietly moving laterally through your switches, mapping domain controllers, and copying hundreds of gigabytes of proprietary customer records, financial spreadsheets, and employee personnel files out to a remote server in another country — a massive **Confidentiality** theft.

Only after the data is exfiltrated do they execute the disk-locking payloads across all virtual hypervisors simultaneously, wiping out local hyper-v storage and hitting **Availability**. When the CEO tells the press "we don't need to pay because we have backups," the ransomware cartel emails a sample of the stolen employee Social Security numbers to the local newspaper and threatens to publish the full database online unless the ransom is wired within forty-eight hours. That is double extortion — attacking two legs of the triad to take away your options.

## When It Breaks — The Technician's Triage Rule

When an incident hits your queue, resist the urge to start changing settings randomly. Stop and categorize the damage:

If someone saw something they shouldn't have, that is Confidentiality — your immediate response is containment: revoke credentials, kill active sessions, rotate API keys, and isolate the compromised host from the network.

If data was changed, corrupted, or backdoored, that is Integrity — your response is verification: pull clean forensic images, compare cryptographic hashes against known-good baselines, and trace unauthorized database transactions in the audit logs.

If the service is unreachable or locked down, that is Availability — your response is restoration: verify failover clusters, initiate DDoS scrubbing, and validate your immutable offline backup sets before spinning up replacement infrastructure.

Every ticket you touch in your career will trace back to one of these three questions. The techs who advance into senior engineering roles aren't the ones who memorized every syntax flag; they're the ones who recognize which rule broke and deploy the right control without wasting time.
