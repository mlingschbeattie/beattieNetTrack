## Where Does Your Data Live Right Now?

When non-technical users hear the word "encryption," they assume it is a single magic button you turn on once.

In reality, digital data is constantly moving and changing form. 

A customer's credit card number might sit stored in a database on an NVMe SSD for six months, travel across an international fiber optic cable in 20 milliseconds, and sit in a CPU register for 4 nanoseconds while an invoice is calculated.

To protect sensitive records, security architects evaluate **Data States**—applying specific cryptographic controls to protect data **At Rest**, **In Transit**, and **In Use**.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        THE THREE STATES OF DATA                        │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   [ 1. DATA AT REST ] ───────────────────────────────────────────      │
│   • Stored on physical media: SSDs, HDDs, Backup Tapes, USBs           │
│   • Threat: Stolen physical drives, unauthorized local access          │
│   • Defense: **BitLocker, FileVault, LUKS, Database TDE**              │
│                                                                        │
│   [ 2. DATA IN TRANSIT / IN MOTION ] ────────────────────────────      │
│   • Moving across networks: Ethernet cables, Wi-Fi, Internet           │
│   • Threat: Eavesdropping, packet sniffing, Man-in-the-Middle (MitM)   │
│   • Defense: **HTTPS (TLS 1.3), IPsec VPNs, SSH, WPA3**                │
│                                                                        │
│   [ 3. DATA IN USE ] ────────────────────────────────────────────      │
│   • Actively processed in memory: RAM, CPU Caches, Registers           │
│   • Threat: Memory scraping malware, Cold Boot RAM dumps               │
│   • Defense: **Hardware Secure Enclaves (Intel SGX), RAM Encryption**  │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

## 1. Data at Rest vs. Data in Transit vs. Data in Use

```
┌────────────────────────────────────────────────────────────────────────┐
│                        DATA STATES AND CONTROLS                        │
├────────────────────┬────────────────────┬──────────────────────────────┤
│ State of Data      │ Physical Location  │ Primary Cryptographic Control│
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **Data at Rest**   │ Non-volatile SSDs, │ **Full Disk Encryption (FDE)**│
│                    │ HDDs, Cloud S3     │ BitLocker, FileVault, LUKS   │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **Data in Transit**│ Network packets    │ **Transport Encryption**     │
│ *(In Motion)*      │ across WAN / LAN   │ TLS 1.3, IPsec VPN, SSH, WPA3│
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **Data in Use**    │ Volatile RAM,      │ **Memory Hardening**         │
│                    │ CPU registers      │ Hardware Enclaves, Clear RAM │
└────────────────────┴────────────────────┴──────────────────────────────┘
```

<Callout type="exam">
**The Backup Trap:** Many companies encrypt their live database on their main server, but save the daily database backup to an **unencrypted external USB drive** stored in a desk drawer. If an attacker steals that USB drive, the server's encryption is completely meaningless! **Data at Rest encryption must apply to all backups, archives, and offline storage media.**
</Callout>

## 2. Regulatory Compliance: PCI-DSS, HIPAA, and PII

Certain types of data carry strict legal mandates requiring encryption across all three states:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        REGULATORY COMPLIANCE TIERS                     │
├──────────────┬──────────────────┬──────────────────────────────────────┤
│ Regulation   │ Protected Data   │ Mandatory Security Requirements      │
├──────────────┼──────────────────┼──────────────────────────────────────┤
│ **PCI-DSS**  │ Payment Card     │ **Never store CVV security codes.**  │
│              │ Data (Credit)    │ Encrypt card numbers at rest and in  │
│              │                  │ transit with AES-256 / TLS 1.3.      │
├──────────────┼──────────────────┼──────────────────────────────────────┤
│ **HIPAA**    │ Protected Health │ Strict access controls, audit logs,  │
│              │ Information (PHI)│ and encryption for medical records.  │
├──────────────┼──────────────────┼──────────────────────────────────────┤
│ **FERPA**    │ Student Academic │ Protects student grades, discipline, │
│              │ Records          │ and IEPs from unauthorized disclosure│
└──────────────┴──────────────────┴──────────────────────────────────────┘
```

## Why This Matters in the Field

When you audit a corporate network or configure a cloud application, you must evaluate where sensitive data travels at every step of its lifecycle.

Ensuring that data is encrypted while resting on disk, encrypted while flying across Wi-Fi, and isolated while executing in memory guarantees end-to-end cybersecurity.
