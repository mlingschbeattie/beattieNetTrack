## Proving Who You Are

When you walk into a secure government facility, the security guard does three things:
1. They ask for your photo ID to verify you are really John Doe (**Authentication**).
2. They check their visitor log to see if John Doe is allowed into the 4th-floor server room (**Authorization**).
3. They record the exact timestamp you entered the building in the audit ledger (**Accounting**).

This is the **AAA Security Framework**: the universal gold standard for access management across corporate networks, firewalls, cloud platforms, and operating systems.

The first and most critical gate in this framework is **Authentication**: proving your identity beyond a reasonable doubt before a computer grants you entry.

```
┌────────────────────────────────────────────────────────────────────────┐
│                         THE AAA SECURITY FRAMEWORK                     │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   [ 1. AUTHENTICATION ] ──> "Who are you?"                             │
│                             (Verify Identity: Password + MFA Token)    │
│            │                                                           │
│            ▼                                                           │
│   [ 2. AUTHORIZATION ]  ──> "What are you allowed to do?"              │
│                             (Check Permissions: Read/Write/Delete)     │
│            │                                                           │
│            ▼                                                           │
│   [ 3. ACCOUNTING ]     ──> "What did you actually do?"                │
│                             (Audit Logs: Timestamped Event Trail)      │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

## 1. The Three Core Factors of Authentication

Security engineers classify all authentication mechanisms into three distinct factor types:

```
┌────────────────────────────────────────────────────────────────────────┐
│                     THE THREE AUTHENTICATION FACTORS                   │
├────────────────────┬────────────────────┬──────────────────────────────┤
│ Factor Category    │ Core Definition    │ Real-World Examples          │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **1. Something**   │ Secret knowledge   │ Passwords, PIN numbers,      │
│ **You KNOW**       │ stored in memory   │ security question answers    │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **2. Something**   │ Physical possession│ Hardware tokens (YubiKey),   │
│ **You HAVE**       │ of a unique device │ Smart cards, TOTP apps       │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **3. Something**   │ Inherent biological│ Fingerprint scans, FaceID,   │
│ **You ARE**        │ characteristics    │ Retina / Iris vascular scans │
└────────────────────┴────────────────────┴──────────────────────────────┘
```

## 2. Multi-Factor Authentication (MFA): The Golden Rule

Single-factor authentication (using a password alone) is dead. Hackers steal billions of credentials every year using automated phishing campaigns, credential stuffing, and malware keyloggers.

**Multi-Factor Authentication (MFA)** requires a user to provide credentials from **at least two DIFFERENT factor categories**:
- ✔ **Password (Know) + Authenticator App Code (Have) = TRUE MFA!**
- ✔ **PIN (Know) + Fingerprint Scan (Are) = TRUE MFA!**
- ❌ **Password (Know) + Security Question (Know) = NOT MFA!** (Using two items from the same factor category is still single-factor security!)

```
┌────────────────────────────────────────────────────────┐
│             THE MULTI-FACTOR AUTHENTICATION RULE       │
│                                                        │
│   ✔ Password (Know) + YubiKey (Have)  ──> MFA PASSED!  │
│   ✔ PIN (Know) + Face ID (Are)        ──> MFA PASSED!  │
│                                                        │
│   ❌ Password (Know) + PIN (Know)      ──> NOT MFA!    │
│   (Two knowledge factors is just 2 passwords!)         │
└────────────────────────────────────────────────────────┘
```

<Callout type="warn">
**The SMS Text Verification Hazard:** Many consumer websites still send 6-digit codes via SMS text messages. However, cybercriminals frequently execute **SIM Swapping Attacks**—tricking mobile phone carrier support into porting the victim's phone number to a hacker's SIM card. **Always recommend app-based TOTP (Google Authenticator) or physical FIDO2 hardware keys over SMS text verification.**
</Callout>

## 3. Single Sign-On (SSO): Convenience vs. Risk

In large enterprises, employees use 40 different cloud tools: Microsoft 365, Salesforce, Slack, Jira, and Workday.

**Single Sign-On (SSO)** uses centralized Identity Providers (IdPs) like **Microsoft Entra ID (Azure AD)** or **Okta**:
- The user logs in once in the morning with a strong password and MFA token.
- Secure cryptographic tokens (SAML 2.0 / OpenID Connect) authenticate the user across all 40 cloud apps automatically.
- **The Security Trade-off:** SSO eliminates password fatigue and weak duplicate passwords, but it creates a high-value single target. If an attacker breaches the user's central SSO account, they gain access to every corporate tool simultaneously!

---

## Why This Matters in the Field

As an IT technician, you will reset user passwords, enroll new employees in MFA authenticator apps, and configure Single Sign-On integrations.

Understanding the AAA model and enforcing strong multi-factor authentication prevents over 99% of automated account takeover attacks.
