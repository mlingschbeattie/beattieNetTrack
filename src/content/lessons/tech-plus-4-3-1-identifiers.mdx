## Giving Names to Memory

At the lowest physical level, a computer stores data in hex memory addresses like `0x7FFF5FBFF8C0`.

If programmers had to remember hex memory addresses every time they wanted to read an employee's name or add two numbers together, writing software would be impossible.

An **Identifier** is a human-readable name assigned to a specific memory location, function, constant, or data structure. The programming language maintains a master lookup symbol table that maps that human name directly to the underlying physical RAM address.

Understanding how to name variables, protect constants, and manage variable scope prevents silent bugs and makes code readable by other engineers.

![Program Memory Mapping and Variable Scope Comparison Guide](/images/tech-plus/identifiers-memory-scope-guide.jpg)

```
┌────────────────────────────────────────────────────────────────────────┐
│                        IDENTIFIER NAMING SCHEMAS                       │
├────────────────────┬────────────────────┬──────────────────────────────┤
│ Convention         │ Example Identifier │ Dominant Programming Usage   │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **camelCase**      │ `userFirstName`    │ Java, JavaScript, C# (Vars)  │
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **snake_case**     │ `user_first_name`  │ Python, Ruby, SQL (Vars/Func)│
├────────────────────┼────────────────────┼──────────────────────────────┤
│ **PascalCase**     │ `UserAccount`      │ Classes / OOP Blueprints     │
├────────────────────┼────────────────────┼──────────────────────────────┤

├────────────────────┼────────────────────┼──────────────────────────────┤
```

<Callout type="exam">
**CompTIA Tech+ Core Objective (FC0-U71 4.3):**
- **Variables vs. Constants:** Variables are mutable storage locations whose values change at runtime. Constants (`UPPER_SNAKE_CASE`) are immutable values defined once that cannot be reassigned.
- **Identifier Rules:** Identifiers cannot begin with numeric digits (e.g., `1st_place` is illegal), cannot contain spaces or hyphens, and cannot match language keywords (`class`, `if`, `while`).
- **Case Sensitivity:** Identifiers are strictly case-sensitive in C++, Java, JavaScript, and Python (`studentId` differs from `studentid`).
- **Scope Lifetime:** Local variables declared inside functions are created on the call stack and destroyed upon function exit. Global variables persist across the entire application runtime.
</Callout>

<Callout type="warn">
**Programming Operational Pitfalls:**
- **Implicit Type Coercion:** Beware of combining different data types. In loosely typed environments, adding an integer to a string (such as `"10" + 5`) performs string concatenation, resulting in `"105"` rather than numerical `15`. Always use explicit casting (`parseInt()` or `int()`).
- **Global Variable Contamination:** Global variables can be mutated by any function anywhere in the project, creating difficult-to-trace state corruption bugs. Limit variables to minimal local scope.
- **Variable Shadowing:** Declaring a local variable with the exact same name as a global variable masks the outer variable, causing confusing bugs where changes to the variable do not reflect globally.
</Callout>

## 1. Variables vs. Constants: Changeable vs. Locked

### Variables (Mutable Containers)
- A **Variable** is a named location in RAM whose stored value is designed to change (mutate) during program execution.
- Examples: A player's score, the current temperature from a sensor, an authentication token.

### Constants (Immutable Locks)
- A **Constant** is a named location in RAM whose value is assigned once and **permanently locked**. Any attempt to overwrite a constant triggers a fatal compilation error.
- Why use constants? They prevent accidental bugs and eliminate *"magic numbers"* in code:
  ```python
  # Bad practice (Magic Number):
  if attempts > 5: lock_user()

  # Best practice (Self-Documenting Constant):
  MAX_LOGIN_ATTEMPTS = 5
  if attempts > MAX_LOGIN_ATTEMPTS: lock_user()
  ```

## 2. Identifier Syntax Rules vs. Style Conventions

You must distinguish between **Hard Syntax Rules** (which cause program crashes if violated) and **Style Conventions** (which make code professional and readable).

```
┌────────────────────────────────────────────────────────────────────────┐
│                         HARD SYNTAX RULES                              │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   ✔ Legal:   `student_grade`, `studentGrade`, `_private_key`, `user1`  │
│                                                                        │
│   ❌ ILLEGAL: `1st_place`        (Cannot start with a numeric digit)   │
│   ❌ ILLEGAL: `first name`       (Cannot contain spaces)               │
│   ❌ ILLEGAL: `user-name`        (Hyphen is interpreted as minus math) │
│   ❌ ILLEGAL: `class`, `if`      (Cannot use reserved language keywords)│
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. Variable Scope: Global vs. Local

**Scope** defines the visibility and lifespan of a variable within a program:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        GLOBAL VS. LOCAL SCOPE                          │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   # GLOBAL VARIABLE (Visible everywhere in the entire file)            │
│   company_name = "Beattie Tech"                                        │
│                                                                        │
│   def calculate_discount(price):                                       │
│       # LOCAL VARIABLE (Exists ONLY inside this function!)             │
│       discount_rate = 0.15                                             │
│       final_price = price * (1 - discount_rate)                        │
│       return final_price                                               │
│                                                                        │
│   # Outside the function:                                              │
│   print(company_name)    # ✔ WORKS (Global)                            │
│   print(discount_rate)   # ❌ CRASHES: "NameError: discount_rate       │
│                          #             is not defined"                 │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

### The Rule of Minimal Scope
Why not make every variable global? If a program has 100 global variables across 20 files, any single line of code could silently overwrite `user_id`, causing bizarre crashes that take days to troubleshoot. 

**Best Practice:** Always declare variables locally within the smallest block of code where they are needed.

## 4. Fundamental Data Types and Type Coercion

When an identifier reserves space in RAM, the computer must know what kind of data it holds so it allocates the correct number of bytes:

```
┌────────────────────────────────────────────────────────────────────────┐
│                     FUNDAMENTAL DATA TYPES                             │
├──────────────┬─────────────────────────┬───────────────────────────────┤
│ Data Type    │ Description             │ Real-World Example            │
├──────────────┼─────────────────────────┼───────────────────────────────┤
│ **Integer**  │ Whole numbers (no dec)  │ `port = 8080`, `count = 42`   │
├──────────────┼─────────────────────────┼───────────────────────────────┤
│ **Float**    │ Decimal numbers         │ `pi = 3.14159`, `rate = 0.08` │
├──────────────┼─────────────────────────┼───────────────────────────────┤
│ **String**   │ Text characters in quotes│ `hostname = "srv-dc01"`       │
├──────────────┼─────────────────────────┼───────────────────────────────┤
│ **Boolean**  │ Binary logical flag     │ `isAuthenticated = True`      │
└──────────────┴─────────────────────────┴───────────────────────────────┘
```

### Static Typing vs. Dynamic Typing
- **Statically Typed (Java, C++, Rust):** You must declare the variable's type when authoring code: `int maxUsers = 50;`. The compiler enforces that you never store text in that integer variable.
- **Dynamically Typed (Python, JavaScript):** The runtime interpreter determines the type based on the assigned value: `max_users = 50`. You can later reassign `max_users = "fifty"` without a compile error, which can cause unexpected runtime bugs.

### Explicit Type Casting vs. Implicit Coercion
When converting between types, always use **explicit casting** rather than relying on the language to guess:
```python
# User inputs from web forms or terminals are ALWAYS strings:
user_input = "25"

# ❌ WRONG: Attempting math on strings causes errors or concatenation
# total = user_input + 5

# ✔ CORRECT: Explicitly cast string to integer
age = int(user_input)
next_year_age = age + 1
print(f"Next year you will be {next_year_age}")
```
