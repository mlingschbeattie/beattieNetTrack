## Keeping Secrets in a Connected World

Every digital system processes sensitive information: healthcare diagnostic logs, student grade transcripts, corporate intellectual property, credit card numbers, and employee credentials.

When confidential records are exposed to unauthorized individuals, the repercussions are catastrophic: identity theft, regulatory sanctions, financial losses, and compromised infrastructure.

**Confidentiality** is the foundational "C" in cybersecurity's **CIA Triad** (Confidentiality, Integrity, Availability). It represents the absolute assurance that data remains shielded from unauthorized observation across all states—whether resting on an NVMe solid-state drive, traversing an optical fiber trunk, or displayed on an office workstation.

<Callout type="exam">
**CompTIA Exam Objective — The CIA Triad:** CompTIA tests your ability to distinguish between the three pillars:
1. **Confidentiality:** Preventing unauthorized disclosure of data (achieved through encryption, access controls, and authentication).
2. **Integrity:** Ensuring data has not been modified or corrupted by unauthorized parties (achieved through hashing and digital signatures).
3. **Availability:** Guaranteeing authorized users have timely, reliable access to resources (achieved through backups, redundancy, and fault tolerance).

## 2. Technical Controls: Locking Down Data

To defend confidentiality, systems administrators implement layered defense-in-depth:

1. **Encryption at Rest:** Converts data stored on non-volatile media into unreadable ciphertext using algorithms like AES-256. If an endpoint is stolen, files remain indecipherable without the cryptographic recovery key. Examples include **Microsoft BitLocker** (Windows), **FileVault** (macOS), and **LUKS** (Linux).
2. **Encryption in Transit:** Scrambles network packets traveling across internal LANs and the internet using **Transport Layer Security (TLS 1.3)**, **Secure Shell (SSH)**, and **IPsec VPN tunnels**. Network sniffers capture only pseudo-random ciphertext.
3. **Multi-Factor Authentication (MFA):** Requires users to validate identity using multiple distinct categories (e.g., password plus a physical FIDO2 hardware token), neutralizing compromised passwords.

<Callout type="warn">
**The Plaintext Transmission Trap:** Never transmit administrative credentials, payment card data, or medical records across unencrypted legacy protocols such as **HTTP (TCP port 80), Telnet (TCP port 23), or FTP (TCP port 21)**. Any station on the local network running a basic packet sniffer can reconstruct full authentication sessions in cleartext.
</Callout>

## 3. Administrative Policies: Least Privilege and Data Classification

Technical cryptography alone cannot protect an organization if permissions are administered recklessly:

- **Principle of Least Privilege (PoLP):** Every user account, service process, and background daemon is restricted to the **bare minimum set of permissions necessary** to execute assigned responsibilities. A shipping clerk requires read access to inventory manifests, never modify access to executive compensation ledgers.
- **Need-to-Know:** Even when a staff member possesses administrative credentials or high security clearance, they are denied access to sensitive project directories unless active work assignments require direct interaction.
- **Data Classification:** Categorizes assets so personnel handle documents in alignment with regulatory mandates:
  - **Public:** Marketing press releases, product manuals, external job postings.
  - **Internal:** Company phone directories, standard operating procedures, intranet notices.
  - **Confidential:** Customer purchase histories, vendor contract drafts, employee evaluations.
  - **Restricted / Top Secret:** Cryptographic private keys, unreleased intellectual property, zero-day threat response playbooks.

## 4. Cryptographic Architecture: Symmetric vs. Asymmetric Algorithms

Modern cryptographic systems combine two fundamental algorithmic families to protect confidentiality:

### Symmetric Encryption (Bulk Data Engine)
Symmetric cryptography utilizes **one identical secret key** for both encryption and decryption:
- **Algorithms:** **AES (Advanced Encryption Standard)** with 128-bit or 256-bit key lengths, ChaCha20.
- **Characteristics:** Extremely fast and hardware-accelerated by modern CPU instruction sets (such as Intel AES-NI). It is the universal standard for encrypting gigabytes of data on hard drives and bulk network streams.
- **The Key Distribution Challenge:** Both parties must securely exchange the secret key beforehand without an adversary intercepting it.

### Asymmetric Encryption (Key Exchange & Identity Engine)
Asymmetric cryptography utilizes a mathematically bound **Key Pair**: a **Public Key** that can be published openly, and a **Private Key** guarded securely by the owner:
- **Algorithms:** **RSA**, **Elliptic Curve Cryptography (ECC)**.
- **Operation:** Data encrypted with the recipient's public key can only be decrypted by the recipient's private key.
- **Hybrid Cryptography:** Modern protocols (such as HTTPS/TLS 1.3) use asymmetric cryptography to authenticate the server and securely negotiate a temporary session key, then switch to high-speed symmetric AES-256 for all subsequent data transport.

## Why This Matters in the Field

Cybersecurity technicians defend data confidentiality across the enterprise lifecycle:
1. **Endpoint Provisioning:** Verifying that Trusted Platform Modules (TPM 2.0) are enabled in UEFI firmware before enrolling laptops into automated BitLocker full-disk encryption policies.
2. **Wi-Fi Hardening:** Decommissioning legacy WEP and WPA protocols in favor of **WPA3-Enterprise**, which enforces individualized session encryption keys preventing neighboring Wi-Fi clients from snooping on each other's traffic.
3. **Decommissioning Storage:** Executing cryptographic erasure or physical shredding on decommissioned solid-state drives to prevent data scavenging via dumpster diving.
