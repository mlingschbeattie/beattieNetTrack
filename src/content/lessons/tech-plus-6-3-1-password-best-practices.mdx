## Password Best Practices

Passwords are the most common authentication mechanism and the most frequently compromised. Good password practices are the single most impactful security habit most users can adopt.

### Why Passwords Fail

**Common attack methods:**
- **Brute force** — trying every possible combination systematically
- **Dictionary attack** — trying a list of common words and passwords
- **Credential stuffing** — using username/password pairs leaked from other breaches
- **Phishing** — tricking users into entering credentials on fake sites
- **Keylogging** — malware records keystrokes, capturing passwords as typed
- **Shoulder surfing** — watching someone type their password

### What Makes a Strong Password

**Length beats complexity.** A 16-character lowercase passphrase is harder to brute-force than an 8-character complex password.

| Characteristic | Recommendation |
|---|---|
| Minimum length | 12 characters (16+ is better) |
| Character variety | Upper, lower, digits, symbols help but length matters more |
| Avoid | Dictionary words, names, dates, "password", keyboard walks (qwerty) |
| Avoid | Personal info (birthday, pet's name, phone number) |

**NIST SP 800-63B** (current US standard) recommends:
- Prioritize **length** over arbitrary complexity rules
- Do **NOT** require frequent mandatory changes (encourages weak patterns like Password1 → Password2)
- **Do** require a change when compromise is known or suspected
- Screen new passwords against lists of known-compromised passwords

### Passphrases

A passphrase is a sequence of random words: `correct-horse-battery-staple`
- Long (28+ characters) but memorable
- Strong against brute force
- Add a number or symbol to meet older site requirements: `correct-horse-battery-staple7!`

### Password Managers

A password manager stores, generates, and auto-fills unique strong passwords for every site.

**Benefits:**
- Never reuse passwords — each site gets a unique, random, long password
- No need to memorize them
- Auto-fill reduces phishing risk (won't fill credentials on non-matching domains)

**Types:**
- **Cloud-based** — syncs across devices (1Password, Bitwarden, Dashlane)
- **Local only** — stored on device only (KeePass); more control, less convenience

The master password to the password manager is critical — make it a strong passphrase and enable MFA on the manager account.

### Password Policies

Organizations enforce:
- **Minimum length** (12+ characters)
- **Lockout policy** — lock account after N failed attempts (blocks brute force)
- **History** — prevent reuse of last N passwords
- **Complexity** — requires mixed character types (balance with usability)
- **MFA enforcement** — passwords alone are not sufficient for sensitive accounts

### Never Do

- Reuse passwords across sites (one breach = all accounts compromised)
- Write passwords on sticky notes
- Share passwords via email or messaging apps
- Use the same password with a number incremented as "rotation"

### Key Exam Points

- **Length > complexity** — longer passphrases are stronger than short complex passwords
- **Credential stuffing** exploits password reuse across sites
- **Password managers** enable unique strong passwords per site without memorization
- NIST no longer recommends mandatory periodic password changes (absent known compromise)
- Account **lockout** after failed attempts is the key control against brute force
