    explanation: "Memory is the most volatile evidence that is practical to capture, and it holds running processes, network connections, encryption keys, and fileless malware that never touched disk."

    options:
      - "It corrupts the file system beyond repair"
      - "It alerts the attacker to the investigation"
      - "It destroys RAM, which may hold encryption keys and in-memory malware"
      - "It invalidates the chain of custody automatically"
    correctIndex: 2
    explanation: "Powering off is a legitimate containment decision, but it destroys the most valuable evidence. With full-disk encryption, losing the in-memory key can make the seized disk unreadable."
  - id: q3
    type: single
    prompt: "What is the purpose of a write blocker during acquisition?"
    options:
      - "It prevents the analysis system from writing to the evidence drive"
      - "It stops malware on the image from executing"
      - "It encrypts the drive while it is transported"
      - "It blocks remote access by the suspect"
    correctIndex: 0
    explanation: "Simply attaching a drive can let the operating system mount it and write recovery data or alter timestamps. A write blocker prevents investigator-caused contamination."
  - id: q4
    type: single
    prompt: "Why hash both the original media and the forensic image?"
    options:
      - "To compress the image for storage"
      - "To prove the copy is identical to the source and detect any later modification"
      - "To encrypt the evidence at rest"
      - "To index the image for keyword searching"
    correctIndex: 1
    explanation: "Matching hashes prove a faithful copy, and re-hashing later proves nothing changed. Use SHA-256 — MD5 is collision-broken and no longer defensible alone."
  - id: q5
    type: single

      - "The drive only needs to be re-hashed to resolve the issue"
      - "Only the report timestamps require correction"
    correctIndex: 1
    explanation: "An opposing party need only argue the evidence could have been altered. A break in the documented chain of custody can waste technically sound findings."
  - id: q6
    type: single
    prompt: "A technician reboots a suspicious machine and runs an antivirus scan that deletes the flagged file. What was lost?"
    options:

      - "Volatile memory, timestamps, unallocated data, and the malware sample itself"
      - "Only the file's creation date"
    correctIndex: 2
    explanation: "The reboot destroys memory and the deletion removes the sample needed to understand the intrusion — while doing nothing about an attacker holding valid credentials or persistence."
  - id: q7

      - "Facial recognition on the subject"
    correctIndex: 0
    explanation: "EXIF metadata is written automatically and travels with the file. It is productive in investigations precisely because people do not know it is there."
  - id: q8

      - "A corrupted image segment"
    correctIndex: 1
    explanation: "Base64 is encoding, not encryption — reversible with no key. An out-of-place encoded string in metadata is a standard investigative lead."
  - id: q9

      - "It works only on plain text files"
    correctIndex: 2
    explanation: "Encryption conceals meaning; steganography conceals existence by hiding data inside an ordinary-looking carrier file. Serious use combines both."
  - id: q10

    correctIndex: 1
    explanation: "A visible edit does not touch EXIF, and the embedded thumbnail is not always regenerated, so the unedited original can survive inside the file. Redaction must remove data, not cover it."
