    options:

      - "A web application firewall in front of the site"

      - "Blocking the keyword SELECT in request parameters"
    correctIndex: 2
    explanation: "Parameterization fixes the query structure before input arrives, so input can only ever be a value. Filtering and WAFs are defense in depth and are routinely bypassed by encoding tricks."

      - "That a WAF blocked the request"

    correctIndex: 0
    explanation: "Time-based blind injection leaks one bit per request using response delay. Suppressing error messages slows this down but does not prevent it."
  - id: q4

      - "Reflected XSS"

      - "DOM-based XSS"
      - "Server-side request forgery"
    correctIndex: 1
    explanation: "Stored XSS is saved on the server and served to every visitor, so it needs no phishing link. Reflected XSS requires a crafted link; DOM-based XSS never reaches the server."
  - id: q5
    type: single
    prompt: "Why is contextual output encoding the correct fix for XSS rather than stripping tags from input?"
    options:
      - "Encoding is faster to execute than filtering"
      - "Encoding removes the need to validate input at all"
      - "Encoding neutralizes data where it is displayed, instead of trying to predict every dangerous input"
      - "Filtering only works against stored XSS"
    correctIndex: 2
    explanation: "Blacklist filters are bypassed by alternative tags, event handlers, and encoding, while also corrupting legitimate data. Encoding at output is decidable because you know where the data is going."
  - id: q6

      - "It forces the cookie to be sent only over HTTP"
    correctIndex: 1
    explanation: "HttpOnly limits the damage of XSS rather than preventing it. The Secure flag restricts the cookie to HTTPS, and SameSite limits cross-site sending."
