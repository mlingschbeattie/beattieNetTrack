    type: short
    prompt: "Which command prints the directory you are currently working in? Give the command only."

  - id: q2
    type: single
    prompt: "In the permission string rwxr-xr--, what access does the group have?"
    options:
      - "Read, write, and execute"
      - "Read and write only"
      - "Read and execute only"
      - "Read only"
    correctIndex: 2
    explanation: "The string splits into three groups of three: owner rwx, group r-x, others r--. The group can read and execute but not write."
  - id: q3
    type: single
    prompt: "Which mode correctly protects an SSH private key?"
    options:
      - "chmod 600 private.key"
      - "chmod 644 private.key"
      - "chmod 755 private.key"
      - "chmod 777 private.key"
    correctIndex: 0
    explanation: "600 gives the owner read and write, and nobody else any access. SSH refuses to use a private key that is readable by group or others."
  - id: q4
    type: short
    prompt: "Convert the permission string rwxr-xr-x to its three-digit octal mode."
    acceptedAnswers: ["755", "0755"]
    explanation: "Read is 4, write is 2, execute is 1. Owner rwx is 7, group r-x is 5, others r-x is 5."
  - id: q5
    type: multi
    prompt: "Select EVERY mode below that lets any user on the system — not just the owner or the group — read the file."
    options:
      - "644"
      - "600"
      - "755"
      - "640"
    correctIndices: [0, 2]
    explanation: "The last digit is others. 644 and 755 both give others a 4 or higher, which includes read. 600 and 640 give others 0. 640 is the common trap — the group can read it, which feels open, but anyone outside the group gets nothing."
  - id: q6
    type: single
    prompt: "Why is chmod 777 on a directory almost always wrong?"
    options:
      - "It prevents the owner from writing to the directory"
      - "It allows any user or process on the system to modify the contents"
      - "It removes the ability to list the directory"
      - "It transfers ownership to root"
    correctIndex: 1
    explanation: "World-writable means exactly that. Any process, including malware running as an unprivileged user, can add or replace files there."
  - id: q7

    prompt: "What does the pipe character do in: cat auth.log | grep 'Failed password' | wc -l"

      - "Sends the output of each command into the input of the next"
      - "Compares the output of the commands for differences"
    correctIndex: 2
    explanation: "Pipes chain simple tools into a single operation. Here the log is filtered to failed logins and then counted."
  - id: q8

      - "cd /var/log"
    correctIndices: [0, 2]
    explanation: "less and head both print what is inside a file — less lets you scroll, head shows the start. ls lists what is in a directory without opening anything, and cd only moves you to a different directory."
  - id: q9
    type: single
    prompt: "What is the difference between > and >> when redirecting output?"

      - "> writes stdout; >> writes stderr"
      - "There is no difference"
    correctIndex: 0
    explanation: "A single > truncates the file first. Using > where you meant >> silently destroys the previous contents."
  - id: q10

    options:
      - "Limits the search to two levels of directories"
      - "Discards error output such as permission-denied messages"
      - "Writes the results to a file named null"
      - "Runs the search with elevated privileges"
    correctIndex: 1
    explanation: "Stream 2 is stderr, and /dev/null discards whatever is written to it. This keeps meaningful results visible amid permission noise."
  - id: q11
    type: short
    prompt: "During an active incident you need to watch /var/log/auth.log update live as new lines are written. Give the command and flag you would use. Including the path is optional."
    acceptedAnswers: ["tail -f", "tail -f /var/log/auth.log", "sudo tail -f", "sudo tail -f /var/log/auth.log", "tail --follow", "tail --follow /var/log/auth.log", "sudo tail --follow /var/log/auth.log"]
    explanation: "tail -f. The -f flag follows the file, printing new lines as they are written. auth.log is usually only readable by root, which is why sudo tail -f is what you will type on a real system."
  - id: q12

    correctIndex: 0

  - id: q13
    type: single
    prompt: "What does find / -perm -4000 locate, and why does it matter?"
    options:
      - "Files modified in the last 4000 minutes, useful for timelines"
      - "Files larger than 4000 bytes, useful for finding archives"
      - "World-writable directories, useful for finding drop locations"
      - "SUID binaries, which run with the owner's privileges and are a privilege escalation target"
    correctIndex: 3
    explanation: "A SUID binary executes with its owner's privileges rather than the caller's. Attackers hunt for vulnerable ones; defenders audit for unexpected ones."
  - id: q14
    type: multi
    prompt: "You suspect a Linux server is compromised and want to investigate without changing anything. Select EVERY command that gathers information without modifying the system."
    options:
      - "ps aux"
      - "find / -perm -4000 2>/dev/null"
      - "chmod 777 /tmp"
      - "whoami"
    correctIndices: [0, 1, 3]
    explanation: "ps aux, find, and whoami only read. chmod changes permissions — and on /tmp it would strip the sticky bit, letting any user delete any other user's files. During triage you observe first; every change you make is a change an investigator later has to account for."
  - id: q15
    type: single
    prompt: "How does kill -9 differ from a plain kill?"
    options:
      - "It sends SIGKILL, which cannot be caught or ignored and skips cleanup"
      - "It restarts the process after terminating it"
      - "It terminates the process only if it is idle"
      - "It kills every process owned by the current user"
    correctIndex: 0
    explanation: "Plain kill sends SIGTERM, which a process can handle and shut down cleanly. SIGKILL is immediate and unblockable, so in-memory data is lost — use it only when SIGTERM fails."
