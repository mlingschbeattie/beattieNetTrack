steps:
  - id: isolate-host
    title: Contain first
    prompt: A workstation is beaconing to an unknown external host and Defender has flagged a suspicious process. What is the first action?
    inputLabel: First action
    hint: Think about what the malware is doing right now, not how to clean it.
    validator:
      type: choice
      options:
        - "Isolate the host from the network, keeping it powered on"
        - "Shut the machine down immediately"
        - "Run a full antivirus scan while it stays online"
        - "Reimage the machine straight away"
      correctIndex: 0
      rationale: "Isolation stops command-and-control traffic and data exfiltration without destroying evidence. Powering off wipes volatile memory an investigator may need. Scanning while online leaves the channel open. Reimaging destroys the evidence entirely and you never learn how it got in."
    successMessage: Correct. Containment comes before cleanup, and evidence is preserved.
  - id: defender-status
    title: Re-enable baseline protection
    prompt: Which built-in Windows protection must you confirm is active and not disabled by the malware?
    inputLabel: Protection control
    validator:
      type: choice
      options:
        - "Microsoft Defender Antivirus real-time protection"
        - "Windows Update delivery optimisation"
        - "User Account Control prompts"
        - "Windows Firewall logging"
      correctIndex: 0
      rationale: "Disabling real-time protection is one of the first things malware attempts, so verifying it is re-enabled is a baseline recovery step. UAC and the firewall matter, but neither provides continuous on-access malware scanning. Note the current product name is Microsoft Defender Antivirus, not Windows Defender."
    successMessage: Correct. Real-time on-access protection must be verified active.
  - id: startup-triage
    title: Startup persistence check
    prompt: You need to find how the malware survives a reboot. Which tool gives the most complete view of persistence entries?
    inputLabel: Persistence tool
    hint: Some tools show only a subset of the places malware can hide.
    validator:
      type: choice
      options:
        - "Sysinternals Autoruns, which enumerates services, scheduled tasks, and registry Run keys"
        - "Task Manager's Startup tab"
        - "The Startup folder in the Start menu"
        - "msconfig"
      correctIndex: 0
      rationale: "All four show something, but Autoruns is the most complete: it covers registry Run keys, services, drivers, scheduled tasks, and shell extensions. Task Manager's Startup tab and msconfig show only a narrow slice, and the Startup folder covers just one location — malware rarely stops there."
    successMessage: Correct. Autoruns covers the persistence locations the others miss.
  - id: encryption-policy
    title: Data protection control
    prompt: Which Windows feature limits the breach impact if this laptop is later lost or stolen?
    inputLabel: Data-at-rest control
    validator:
      type: choice
      options:
        - "BitLocker full-disk encryption"
        - "A strong Windows sign-in password"
        - "Encrypting the user's Documents folder with EFS"
        - "Windows Hello facial recognition"
      correctIndex: 0
      rationale: "BitLocker encrypts the whole volume, so pulling the drive and mounting it elsewhere yields nothing readable. A sign-in password and Windows Hello only guard the logon path and are bypassed entirely by removing the disk. EFS protects selected files but leaves the rest of the volume, including temp files, exposed."
    successMessage: Correct. Full-disk encryption is what protects data at rest.
  - id: closure
    title: Ticket closure standard
    prompt: Write one line that includes both words "verified" and "hardened".
    inputLabel: Closure note
    placeholder: "ex: Verified endpoint clean and hardened baseline controls restored."
    validator:
      type: regex
      pattern: '^(?=.*\bverified\b)(?=.*\bhardened\b).+$'
      flags: "i"
    successMessage: Strong closeout. You documented both verification and hardening.
checklist:
  - Host containment performed before remediation
  - Real-time protection restored
  - Persistence checks completed
  - Data-at-rest control identified
  - Closure note confirms verified hardening
hints:
  - If you cannot explain the order of your actions, your triage plan is not ready.
  - Keep user communication and approval in scope for disruptive steps.
  - Documentation quality is part of technical quality.

This lab reinforces a technician-grade hardening workflow for Windows incident response.
