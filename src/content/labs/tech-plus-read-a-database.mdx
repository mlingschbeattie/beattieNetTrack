## Relational Databases: From Chaos to Structure

Spreadsheets are great for simple lists and personal budgets. But when an organization grows, relying on spreadsheets leads to chaos:
1. **Redundancy:** Retyping customer names across multiple sheets wastes time and leads to spelling mismatches.
2. **Integrity Failures:** Updating an address in one tab while forgetting another creates conflicting data.
3. **Concurrency:** Multiple users editing a single file leads to lockouts and corrupted saves.

A **Relational Database Management System (RDBMS)** structures data into normalized tables connected by **Primary Keys** and **Foreign Keys**, queried cleanly using **Structured Query Language (SQL)**.

<Callout type="exam">
CompTIA Tech+ FC0-U71 tests the fundamental building blocks of databases: Primary Keys (unique row identifiers), Foreign Keys (links to parent tables), basic SQL queries (`SELECT`, `WHERE`), CRUD operations (`INSERT`, `SELECT`, `UPDATE`, `DELETE`), and the difference between structured relational databases vs unstructured big data.
</Callout>

<Callout type="warn">
Never run an `UPDATE` or `DELETE` SQL statement without a `WHERE` clause! In SQL, running `DELETE FROM students;` without a `WHERE student_id = 1042;` condition will permanently wipe every single student row in the entire table in a fraction of a second.
</Callout>
